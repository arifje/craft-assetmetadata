# Changelog

## 5.2.0 - 2026-09-11

### Added
- Verified Craft CMS 5 support from the same code base that supports Craft CMS 4; both versions are covered by the test suite.
- A `maxValueLength` config setting (default `65535`) that limits the length of rendered subfield values, so oversized metadata can’t break saving an asset.
- The `asset-metadata/extract` console command now exits with a non-zero status and a clear message when the asset or its file can’t be found.
- Subfield handles are validated when the field settings are saved (they must be unique and start with a letter or underscore, followed by letters, numbers or underscores).
- Unit and integration test suites, a Docker harness for Craft 4 and Craft 5 (`bin/dev`), PHPStan configuration and a CI workflow.

### Changed
- Metadata is now also extracted when an asset’s file is replaced (previously only on upload, on “Refresh”, or on every save when “Refresh on element save” is enabled).
- When a file can’t be read (missing file, failed download from a remote filesystem), the stored metadata is kept instead of being overwritten with empty values.
- Rendered subfield values are sanitized to valid UTF-8 without NUL bytes before they are stored.
- getID3 diagnostics are logged at the `warning`/`info` levels instead of `error`; unsupported file types are normal input, not plugin failures.
- The “Refresh” button no longer appears for assets that haven’t been saved yet, and it reports errors in the control panel instead of failing silently.
- `Metadata::getFieldValue()` returns `null` when the asset’s file can’t be analyzed, and `Metadata::extract()` throws a `MetadataException` in that case. `EVENT_AFTER_EXTRACT` is now triggered on the service instance (`$event->sender`), which still reaches class-level listeners.
- The `convertExifGpsCoordinates` filter’s `format` argument is optional now (default: sexagesimal string).

### Fixed
- Craft 5: element index columns for subfields are rendered through `EVENT_DEFINE_ATTRIBUTE_HTML` (and in inline-editing mode), Craft 4 keeps using `EVENT_SET_TABLE_ATTRIBUTE_HTML`; the version check no longer references constants that don’t exist in the other version.
- Craft 5: field values are stored with the correct JSON DB type.
- The “Refresh” button never updated the inputs because the returned values are keyed by subfield ID (an object, not an array).
- “Refresh on element save” only refreshed the first asset saved in a request; bulk resaves and queue jobs now refresh every asset, while each asset is still analyzed only once per request (also when it propagates to other sites).
- Images without EXIF data (or with the `0000:00:00 00:00:00` placeholder date) broke saving the asset with a `TypeError` in the `convertExifDate` filter; the same applied to non-numeric input for the GPS and number filters, `floatToFraction(0)`, and `numeralSystem` with a `zero` argument other than `-1`/`1`.
- `unitPrefix` lost the decimals of exact values (`1.50` became `1`).
- Traversing a metadata path through a scalar value (`--key=mime_type.charset`) threw a `TypeError`.
- Malformed stored field values (invalid JSON) no longer throw when the asset is loaded.
- GraphQL: fields without subfields no longer break the schema, and missing subfield values resolve to `null`.
- Temporary copies of files from remote filesystems are always removed, also when the download or analysis fails; partial downloads no longer leak file handles.
- A leftover debug log line in the refresh action that wrote the extracted metadata to the log at `error` level was removed.

### Security
- Subfield values shown as element index columns are HTML-encoded now. Metadata comes straight from uploaded files, so a crafted tag could inject markup into the control panel before.
- The refresh action requires a POST control panel request (with CSRF token) by a user who is allowed to view the asset in question. Previously any logged-in user could extract the metadata (including GPS coordinates) of any asset by ID.
- Temporary file names are generated by the plugin instead of being derived from the asset’s filename.

## 3.0.0-beta.1 - 2018-06-10

### Added
- Added Craft 3 compatibility.
- Added the `EVENT_AFTER_GET_METADATA` event to `carlcs\assetmetadata\services\Metadata`.

### Changed
- The field always shows the “Refresh” button now when its “Make read-only” field setting isn’t enabled.
- Extracting metadata from Assets on remote Asset Volumes can now be configured with the `downloadChunkSize` and `fakeCompleteFileSize` config settings. The `remoteAssetSources` config setting was removed.
- Updated getID3 to version 1.9.15

### Removed
- Removed support to add the field to an element’s field layout if it’s not an Asset Volume.
- Removed the ability to set the field’s Translation Method, it defaults to “none” now.
- The “Custom Metadata“ and the “Show refresh button” field settings were removed.
